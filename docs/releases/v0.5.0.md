# Focus Island v0.5.0 — Jira tasks on your focus board

Import selected Jira issues into Focus Island and work on them with the existing Claude Code and Codex sessions, focus timers, notes, criteria, and reports.

**Jira import correction:** post-release live verification found that this version requests search fields rejected by ACLI 1.3.39. Upgrade to [v0.5.1](https://github.com/mpakus/focus-island/releases/tag/v0.5.1), which fixes the request and passes live import/refresh verification.

## Jira import preview

- **Choose your work:** browse assigned, unfinished issues and import selected items into Backlog or Todo, optionally choosing a local project folder.
- **Keep progress personal:** Jira status appears beside the issue key, separately from the local column. Closing a focus task never transitions the Jira issue.
- **Refresh without losing local work:** update source titles, descriptions, and status while retaining notes, sessions, criteria, prompts, timers, ordering, and completion history. Reimporting an issue reuses its card.
- **Work offline:** cached tasks remain available. Disconnect preserves cards and history; detach makes source text locally editable.
- **Use Atlassian's sign-in:** install Atlassian CLI separately, run `acli jira auth login --web`, then choose Settings → Focus → Jira → Connect signed-in account. The app invokes read commands and never collects API tokens or reads CLI credential files.
- English, Spanish, and Russian interface text is included.

## Installation and setup

1. Download `Focus.Island.dmg` or `Focus.Island.zip`. Both contain a universal app and helpers for Apple Silicon and Intel, requiring macOS 14 or later.
2. Replace the previous app in Applications. This build uses ad-hoc signing and is **not notarized by Apple**. If macOS blocks it, attempt to open it and use System Settings → Privacy & Security → Open Anyway.
3. Install [Atlassian CLI](https://developer.atlassian.com/cloud/acli/guides/install-macos/) and sign in using its browser flow. Supported executable locations are `/opt/homebrew/bin/acli`, `/usr/local/bin/acli`, and `~/.local/bin/acli`.
4. Connect in Settings → Focus → Jira, then open the board and choose Jira → Add from Jira. Use Jira → Refresh linked tasks for manual updates.

Jira is optional. Existing local tasks, Claude Code, and the Codex preview continue to work without ACLI.

## Preservation and scope

Database migration `v7` creates a consistent `before-jira-*.sqlite` snapshot before upgrading an existing database. Task IDs, agent sessions, local history, and timers are preserved. Migration errors retain the original database; imports are disabled if durable storage is unavailable. Prefer disconnecting to restoring an old backup, which would discard newer work.

This first slice supports one Jira Cloud account/site at a time and ordinary `*.atlassian.net` domains. It uses manual refresh and text-only descriptions. Native OAuth, automatic polling, Data Center, custom domains, workflow transitions, comments, attachments, worklogs, and sprint mirroring are outside this release.

The inspected ACLI version is `1.3.39-stable`. The full suite passed with 915 tests reported across 88 suites; two optional checks (live Jira and the localized settings preview) were skipped. Checks cover import identity, migration/backup, local-data preservation, stale editor saves and selections, malformed/incomplete responses, account changes, cancellation, and process bounds. All 982 localization keys passed validation, and the Jira setup/import/task rendering check passed separately. Standards and specification reviews completed with their findings fixed.

Universal packaging preflight passed for the app and helpers, including signatures and launching outside the repository. Live authenticated CLI acceptance was pending when v0.5.0 shipped; the later check found the search-field issue described above. This integration is an opt-in preview.

See the [implementation and validation record](../JIRA-INTEGRATION-PLAN.md) for the exact support boundary. Existing Codex preview limitations remain as documented in the README.
